# Portal AI — מדריך הפעלה ושימוש

המדריך מסביר איך מריצים את Portal AI (Leg 1) על המחשב, איך משתמשים בשלושת האזורים (מרקטפלייס, קהילה ונתוני שימוש) ואיך מפתחים עליו.

## מה יש במערכת

- **ממשק:** אתר React בעברית, תחת הכתובת `/AI`.
- **ארבעה שירותי שרת** (FastAPI), לכל אחד מסד נתונים משלו:
  - `auth`: התחברות.
  - `marketplace`: הקטלוג.
  - `community`: פוסטים ותגובות.
  - `usage`: נתוני שימוש.
- **NGINX:** נקודת כניסה אחת שמעבירה כל בקשה לשירות הנכון.
- **Postgres:** מסד הנתונים.

הכול רץ ב-Docker, ובהפעלה הראשונה נטענים אוטומטית נתוני דמו.

## מה צריך להתקין

- Docker עם Docker Compose (הפקודה `docker compose`).
- `make`.
- רק אם מפתחים בלי Docker: [uv](https://docs.astral.sh/uv/) ו-Node 22.

## הפעלה

מתיקיית הפרויקט:

```bash
make dev
```

אחרי שהכול עולה, פותחים את **http://localhost:8080/AI/**. אפשר לפתוח את האתר גם ממחשב אחר ברשת, בכתובת ה-IP של המחשב שמריץ אותו (למשל `http://10.0.0.5:8080/AI/`).

- **הפעלה ראשונה:** הבנייה לוקחת כמה דקות, בעיקר בגלל התקנת חבילות ה-npm. בסיומה נוצרים מסדי הנתונים ונטענים נתוני הדמו.
- **הפעלה ברקע:** `make dev` רץ בחלון הנוכחי, ו-Ctrl+C עוצר אותו. כדי להריץ ברקע: `docker compose up -d --build`. כדי לעצור: `make down`.
- **בדיקה שהכול עלה:** הריצו `docker compose ps`. ארבעת השירותים צריכים להופיע כ-`healthy`.

## התחברות: עם SSO או בלי

בוחרים את אופן ההתחברות בפקודת ההפעלה. בכל שלושת המצבים אפשר להתחבר גם עם שם משתמש וסיסמה.

| מצב | פקודה | מה רואים במסך ההתחברות |
|---|---|---|
| SSO מדומה (ברירת המחדל) | `make dev` | לחיצה על כפתור ה-SSO מחברת מיד, בלי לשאול כלום |
| SSO אמיתי | `make dev sso=keycloak` | לחיצה על כפתור ה-SSO מעבירה למסך ההתחברות של ספק זהויות (Keycloak), ומשם חוזרים מחוברים |
| בלי SSO | `make dev sso=off` | אין כפתור SSO. מופיע רק טופס שם משתמש וסיסמה |

- **מעבר בין מצבים:** מריצים שוב `make dev` עם המצב החדש. אין צורך לעצור קודם. כשיוצאים ממצב `keycloak`, הוא נעצר לבד.
- **בחירה קבועה:** מעתיקים את `.env.example` ל-`.env` וקובעים שם `SSO_MODE=off` (או `dev`). כדי להריץ תמיד עם Keycloak, מבטלים שם את ההערה בשורה `COMPOSE_FILE=...`. מעכשיו `make dev` ו-`docker compose up` משתמשים בבחירה הזו.

### SSO מדומה

בסביבת פיתוח רגילה אין ספק זהויות ארגוני. במקומו יש ספק דמה שעובר באותו מסלול כמו SSO אמיתי: מעבר לספק, חזרה לאתר ויצירת עוגיית סשן. ההבדל הוא שהוא לא שואל מי אתם, אלא מחבר משתמש קבוע.

- **המשתמש שמתחבר:** `alon.cohen` כברירת מחדל.
- **החלפת המשתמש:** ב-`.env` משנים את `SSO_DEV_USERNAME` (למשל ל-`elad.biton`) ומריצים שוב `make dev`.

### SSO אמיתי עם Keycloak

`make dev sso=keycloak` מוסיף לסביבה את [Keycloak](https://www.keycloak.org/), ספק זהויות אמיתי, שמשמש כאן כספק הזהויות הארגוני. ההתחברות עוברת ב-OpenID Connect, בדיוק כמו מול ספק הזהויות של הארגון (Entra ID, Okta, ADFS).

- **הפעלה ראשונה:** Docker מוריד את Keycloak (כ-450MB), ולוקח לו כדקה לעלות. השירותים מחכים לו.
- **התחברות:** לוחצים על כפתור ה-SSO, ובמסך של Keycloak מזינים משתמש מהטבלה למטה עם הסיסמה `portal123`.
- **משתמש בלי גישה:** ב-Keycloak יש גם את `dana.levi`, שאין לו חשבון ב-Portal AI. ההתחברות איתו נכשלת, ומופיעה הודעת שגיאה במסך ההתחברות.
- **החלפת משתמש:** Keycloak זוכר שהתחברתם, וזה בדיוק מה ש-SSO עושה: בפעם הבאה הכפתור מחבר מיד. כדי להתחבר כמשתמש אחר, פותחים חלון גלישה בסתר או מתנתקים מ-Keycloak בכתובת http://localhost:8180/realms/portal/account.
- **ניהול Keycloak:** http://localhost:8180/admin, משתמש `admin`, סיסמה `admin`. המשתמשים וההגדרות נטענים מהקובץ `deploy/keycloak/portal-realm.json` בכל הפעלה.
- **במצב הזה פותחים את האתר רק בכתובת `localhost`**, כי Keycloak מחזיר את הדפדפן לכתובת הזו.

### שם משתמש וסיסמה

| משתמש | סיסמה | מה רואים |
|---|---|---|
| `alon.cohen` | `portal123` | ראש מדור: "ה-AI שלי" וגם "ה-AI תחתיי" (מדור פלטפורמות נתונים, 24 משתמשים) |
| `elad.biton` | `portal123` | מהנדס: רק "ה-AI שלי" |
| `portal.admin` | `portal123` | מנהל מערכת: ה-API מאפשר לו לערוך ולמחוק כל תוכן |

### החלפת משתמש

- **אין כפתור התנתקות בממשק**, כמו בדמו. כדי להיכנס כמשתמש אחר, פותחים חלון גלישה בסתר או מוחקים את העוגייה `portal_session`. במצב `keycloak` צריך להתנתק גם מ-Keycloak (ראו למעלה).
- **תוקף:** סשן תקף ל-12 שעות.
- **כניסה לעמוד בלי התחברות:** מועברים למסך ההתחברות. אחרי ההתחברות חוזרים בדיוק לעמוד שביקשתם.

## שימוש במערכת

### מרקטפלייס

- **עיון:**
  - חיפוש חופשי לפי שם, תיאור, מפרסם או תגית.
  - סינון לפי סוג (Connectors, Skills, Agents, Plugins, Apps), לפי קטגוריה ולפי תגיות. כשבוחרים כמה תגיות, יוצגו רק פריטים שיש להם את כולן.
  - מיון: חדשים, הכי מותקנים, הכי הרבה כוכבים.
- **פריט:** לחיצה על כרטיס פותחת חלון עם הפרטים והוראות ההתקנה.
  - **כוכב:** מסמנים ומבטלים באותו כפתור, והמספר מתעדכן מיד בכרטיס ובחלון.
  - **ספירת התקנות:** העתקת פקודת התקנה, הורדת ZIP או הורדת אפליקציה מוסיפים התקנה אחת. כל משתמש נספר פעם אחת לכל פריט.
- **פרסום:**
  1. לוחצים "+ פרסום" וממלאים את הטופס. השדות משתנים לפי הסוג.
  2. לוחצים "המשך".
  3. מאשרים שהתוכן גלוי לכל הארגון, בתיבת סימון שהיא חובה.
  4. לוחצים "פרסום לכל הארגון".

  אפליקציות (Apps) עדיין אי אפשר לפרסם מהטופס.
- **ההעלאות שלי:** כאן רואים את מה שפרסמתם. אפשר לצפות, לערוך (בלי שלב האישור) ולמחוק.
- **קישור ישיר:** `/AI/marketplace/<מזהה>` פותח פריט ישירות.

### קהילה

- **עיון:**
  - חיפוש לפי טקסט, מחבר או תגית.
  - סינון לפי קטגוריה (טיפים, שאלה, הצג וספר, דיון) ולפי תגיות. כשבוחרים כמה תגיות, יוצגו רק פוסטים שיש להם את כולן.
  - מיון: החדשים תחילה, או הפוסטים המובילים.
- **פוסט חדש:**
  - אפשר לצרף תמונות (מוקטנות אוטומטית) וקבצים, עד 10MB לקובץ.
  - מוסיפים תגית עם Enter או פסיק.
  - לפני הפרסום יש שלב אישור, כמו במרקטפלייס.
- **בתוך פוסט:**
  - "עזר לי": מסמנים ומבטלים באותו כפתור.
  - תגובות: אפשר לערוך ולמחוק תגובות שלכם.
  - שיתוף מחדש עם תגובה: בלי שלב אישור, כי התוכן כבר גלוי.
  - קישור לשיתוף: הכתובת `/AI/community/<מזהה>`, שפותחת את הפוסט ישירות.
  - פוסט שלכם אפשר לערוך ולמחוק.

### נתוני שימוש

- **שתי לשוניות:**
  - **"ה-AI שלי"** פתוחה לכולם.
  - **"ה-AI תחתיי"** מופיעה רק למי שמנהל יחידה, למשל `alon.cohen`. השרת חוסם כל ניסיון לראות נתונים מחוץ להיררכיה שלכם.

  - לחיצה על משתמש פותחת את התצוגה האישית שלו.

  - אפשר לייצא את רשימת המשתמשים ל-CSV.
- **נתוני הדמו:** הנתונים מסתיימים ב-28.10.2026, ולכן "היום" בגרפים הוא היום האחרון שיש לו נתונים.

## פיתוח

- **שינויים בקוד נטענים לבד:**
  - שרת: קוד ב-`services/*/src` או ב-`libs/portal-kit/src` טוען מחדש את השירות.
  - ממשק: שינוי ב-`frontend/src` מתעדכן בדפדפן בלי רענון.
- **לוגים:** `make logs`, או לשירות אחד: `docker compose logs -f community`.
- **בדיקות ואיכות קוד:**
  - `make test`: בדיקות שרת וממשק.
  - `make lint`: ruff, mypy, ESLint ו-TypeScript.
  - `make fmt`: עיצוב אוטומטי לקוד השרת.
- **שינוי מבנה מסד הנתונים:** אחרי שינוי במודלים ב-`infrastructure/orm.py`:

  ```bash
  make migration svc=community m="add reactions"
  ```

  קובץ המיגרציה נוצר ב-`services/community/migrations/versions/` ומופעל אוטומטית בהפעלה הבאה של השירות (`docker compose restart community`).
- **איפוס הנתונים:** `make reset`, ואז `make dev`. כל המידע נמחק ונתוני הדמו נטענים מחדש.
- **הוספת חבילות:**
  - Python:

    ```bash
    uv add --package community-service <חבילה>
    docker compose up -d --build community
    ```

  - ממשק (מתוך התיקייה `frontend`):

    ```bash
    npm install <חבילה>
    docker compose up -d --build -V frontend
    ```

- **הרצה בלי Docker:** ההוראות נמצאות ב-[README](../README.md#development-without-docker).

## הרצה מקומית של גרסת פרודקשן

גרסת פרודקשן משתמשת ב-images הסופיים, בלי טעינה מחדש. קודם עוצרים את סביבת הפיתוח (`make down`), כי שתיהן משתמשות בפורט 8080. אפשר גם להריץ על פורט אחר עם `GATEWAY_PORT=8090`.

```bash
JWT_SECRET=$(openssl rand -hex 32) make prod
```

לעצירה: `docker compose -f docker-compose.prod.yml down`.

בגרסת פרודקשן עוגיית הסשן מוגדרת `Secure`, ולכן דפדפנים שומרים אותה רק ב-HTTPS או בכתובת `localhost`. כדי לבדוק אותה ב-HTTP רגיל ממחשב אחר, מוסיפים לפקודה `COOKIE_SECURE=false`. בלי זה, ההתחברות מחזירה שוב למסך ההתחברות.

## חיבור לספק הזהויות של הארגון

שירות ה-auth מדבר OpenID Connect עם כל ספק זהויות שתומך בו (Entra ID, Okta, ADFS, Keycloak). זה אותו קוד שרץ במצב `sso=keycloak`, ולכן אין מה לממש. צריך רק להגדיר:

1. **לרשום את Portal AI אצל ספק הזהויות** כאפליקציית web, עם כתובת החזרה `https://<host>/AI/api/auth/sso/callback` (בפיתוח: `http://localhost:8080/AI/api/auth/sso/callback`). מקבלים מהספק Client ID ו-Client secret.
2. **להגדיר משתני סביבה** לשירות ה-auth (בפיתוח: בקובץ `.env`):

   | משתנה | ערך |
   |---|---|
   | `SSO_MODE` | `oidc` |
   | `OIDC_ISSUER` | כתובת ה-issuer של הספק. למשל ב-Entra ID: `https://login.microsoftonline.com/<tenant-id>/v2.0` |
   | `OIDC_CLIENT_ID` | ה-Client ID |
   | `OIDC_CLIENT_SECRET` | ה-Client secret |
   | `PUBLIC_URL` | הכתובת שבה המשתמשים פותחים את האתר, למשל `https://portal.example.com` (רק בפרודקשן; בפיתוח היא נקבעת לבד) |

3. **להריץ ב-HTTPS.** בפרודקשן עוגיית הסשן מוגדרת `Secure`.

- **איך משתמש מזוהה:** לפי השדה `preferred_username` באסימון שהספק מחזיר. אם יש בו `@` (למשל `alon.cohen@corp.com`), נלקח החלק שלפניו. החשבון צריך להיות קיים ב-Portal AI. אם לא, ההתחברות נכשלת. אפשר לבחור שדה אחר עם `OIDC_USERNAME_CLAIM`.
- **אבטחה:** ההתחברות משתמשת ב-PKCE, בודקת את החתימה, את ה-issuer, את ה-audience, את התוקף ואת ה-nonce של האסימון, ומוודאת שהתשובה חזרה לאותו דפדפן שהתחיל את ההתחברות.
- **כשמשהו לא עובד:** הסיבה המדויקת נכתבת ללוג של השירות: `docker compose logs auth`.

גרסת פרודקשן מסרבת לעלות עם ה-SSO המדומה, אלא אם מגדירים במפורש `ALLOW_DEV_IDENTITY_PROVIDER=true`.
